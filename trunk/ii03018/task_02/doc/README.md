## 1. Цель работы

Освоить технологию модульного (юнит-) тестирования программ на C++ с применением
фреймворков **Google Test** и **Google Mock**: научиться проверять правильность
отдельных единиц кода, строить параметризованные тесты, работать с граничными
случаями и физическими инвариантами, измерять тестовое покрытие (`gcovr`) и
трактовать его результаты. Дополнительно — закрепить навыки ООП (наследование,
чисто виртуальные методы, интерфейсы) на примере программы лабораторной работы №1.

## 2. Постановка задачи

Объект тестирования — математическое ядро программы ЛР1 (Вариант 7, папка
`trunk/ii03018/task_01/`): три динамические модели (**Модель 1.7** — линейная с
памятью по входу, **Модель 2.9** — нелинейная корневая со знаком, **Модель 3.1** —
дифференциальное уравнение первого порядка, решаемое методом Эйлера), три режима
входных воздействий (ступень, импульс, гармоника) и модуль анализа устойчивости
линейной модели 1.7 на Z-плоскости.

Требования:

1. покрыть программу модульными тестами с помощью **Google Test**, автоматизировать
   сборку и запуск через CMake / `ctest` (`run_tests.bat`);
2. проверить **правильность вычислений** моделей на наборах параметров,
   рассчитанных вручную;
3. разработать и протестировать **модуль анализа устойчивости**: возврат `true`
   на устойчивых коэффициентах (|a| &lt; 1), `false` на расходящихся (|a| &gt; 1),
   проверка **граничных случаев** на единичной окружности (|z| = 1) и вывода
   предупреждения `[WARNING]` в консоль;
4. проверить **граничные значения нелинейности** для Модели 2.9 (точка излома
   u = 0 и смена знака sign(u) при положительном и отрицательном входе);
5. проверить **физические инварианты**: сохранение состояния покоя при нулевом
   входе и сходимость метода Эйлера (Модель 3.1) к аналитическому решению;
6. применить **параметризованные тесты** (`TEST_P`, п. 8) для проверки
   сходимости алгоритма на различных наборах данных без дублирования кода;
7. использовать **мок-объекты (Google Mock)** и подмену входного сигнала (п. 9) для тестирования режимов управления (ступень, импульс, гармоника);
8. в отчёте отразить количество тестов и **процент тестового покрытия** (`gcovr`).

## 5. Тестовые сценарии и ручной пересчёт

Все эталонные значения в тестах получены предварительным ручным расчётом по
формулам.

### 5.1. Правильность значений и многошаговая память (`Model1_7Test`)

**Модель 1.7** описывается линейным разностным уравнением с памятью по входу на
два предыдущих такта:

<p align="center"><b><i>y</i><sub>τ+1</sub> = <i>a</i> · <i>y</i><sub>τ</sub> + <i>b</i><sub>1</sub> · <i>u</i><sub>τ</sub> + <i>b</i><sub>2</sub> · <i>u</i><sub>τ−1</sub> + <i>b</i><sub>3</sub> · <i>u</i><sub>τ−2</sub></b></p>

Зададим коэффициенты: <i>a</i> = 0.5, <i>b</i><sub>1</sub> = 2.0, <i>b</i><sub>2</sub> = 1.0, <i>b</i><sub>3</sub> = 0.5.
Начальные условия нулевые: <i>y</i><sub>0</sub> = 0, <i>u</i><sub>−1</sub> = 0, <i>u</i><sub>−2</sub> = 0. Подадим
последовательность входов <i>u</i><sub>0</sub> = 1.0, <i>u</i><sub>1</sub> = 2.0, <i>u</i><sub>2</sub> = 3.0:

1. **Шаг 0** (<i>u</i><sub>0</sub> = 1.0):

   <p align="center"><i>y</i><sub>1</sub> = 0.5 · 0 + 2.0 · 1.0 + 1.0 · 0 + 0.5 · 0 = 2.0</p>

2. **Шаг 1** (<i>u</i><sub>1</sub> = 2.0, <i>u</i><sub>0</sub> = 1.0):

   <p align="center"><i>y</i><sub>2</sub> = 0.5 · 2.0 + 2.0 · 2.0 + 1.0 · 1.0 + 0.5 · 0 = 1.0 + 4.0 + 1.0 = 6.0</p>

3. **Шаг 2** (<i>u</i><sub>2</sub> = 3.0, <i>u</i><sub>1</sub> = 2.0, <i>u</i><sub>0</sub> = 1.0):

   <p align="center"><i>y</i><sub>3</sub> = 0.5 · 6.0 + 2.0 · 3.0 + 1.0 · 2.0 + 0.5 · 1.0 = 3.0 + 6.0 + 2.0 + 0.5 = 11.5</p>

Траектория 2.0 → 6.0 → 11.5 проверяется в тесте `ManualCalculationMultiStepHistory`,
после чего вызывается `reset()` и проверяется возврат к исходному состоянию.

### 5.2. Модуль анализа устойчивости на Z-плоскости (`StabilityAnalyzerTest`)

Применим Z-преобразование к уравнению Модели 1.7 при нулевых начальных условиях:

<p align="center"><b><i>z</i> · <i>Y</i>(<i>z</i>) − <i>a</i> · <i>Y</i>(<i>z</i>) = (<i>b</i><sub>1</sub> + <i>b</i><sub>2</sub> · <i>z</i><sup>−1</sup> + <i>b</i><sub>3</sub> · <i>z</i><sup>−2</sup>) · <i>U</i>(<i>z</i>)</b></p>

Передаточная функция системы:

<p align="center"><b><i>W</i>(<i>z</i>) = <i>Y</i>(<i>z</i>) / <i>U</i>(<i>z</i>) = (<i>b</i><sub>1</sub> · <i>z</i><sup>2</sup> + <i>b</i><sub>2</sub> · <i>z</i> + <i>b</i><sub>3</sub>) / (<i>z</i><sup>2</sup> · (<i>z</i> − <i>a</i>))</b></p>

Характеристическое уравнение <i>z</i><sup>2</sup>(<i>z</i> − <i>a</i>) = 0 имеет тривиальные полюса <i>z</i><sub>1,2</sub> = 0
(всегда лежат в центре единичного круга) и полюс обратной связи <i>z</i><sub>3</sub> = <i>a</i>.
По критерию устойчивости дискретных систем полюс должен лежать **строго внутри**
единичной окружности на Z-плоскости:

<p align="center"><b>|<i>z</i>| &lt; 1 &emsp;⇔&emsp; |<i>a</i>| &lt; 1</b></p>

Проверяемые в тестах случаи:

| Тест | Коэффициент <i>a</i> | Положение полюса на Z-плоскости | Ожидаемый результат |
|---|:--:|---|:--:|
| `ReturnsTrueForStableCoefficients` | 0.0; ±0.5; ±0.999 | Строго внутри единичного круга (\|<i>z</i>\| &lt; 1) | `true` (STABLE) |
| `ReturnsFalseOnBoundaryOfUnitCircle` | +1.0; −1.0 | **Ровно на границе окружности (\|<i>z</i>\| = 1)** | `false` (UNSTABLE) |
| `ReturnsFalseForUnstableCoefficients` | 1.5; −2.0; 100.0 | Вне единичного круга (\|<i>z</i>\| &gt; 1, разнос) | `false` (UNSTABLE) |
| `PrintsWarningWhenConstructedWithUnstableCoeff` | 1.2 | Вне круга + перехват потока `std::cout` | `false` + строка `[WARNING]` |

### 5.3. Граничные значения нелинейности (`Model2_9Test`)

**Модель 2.9** описывается нелинейным уравнением:

<p align="center"><b><i>y</i><sub>τ+1</sub> = <i>a</i> · <i>y</i><sub>τ</sub> + <i>b</i> · √|<i>u</i><sub>τ</sub>| · sign(<i>u</i><sub>τ</sub>)</b></p>

Точкой излома (граничным значением нелинейности) является точка смены знака
<i>u</i> = 0.0. При <i>a</i> = 0.5, <i>b</i> = 2.0 и <i>y</i><sub>0</sub> = 0.0 в тесте `BoundaryAndSignNonLinearity`
проверяются все три участка характеристики:
1. **Граничная точка <i>u</i> = 0.0:** sign(0) = 0 ⇒ <i>y</i><sub>1</sub> = 0.0.
2. **Положительная ветвь <i>u</i> = 4.0 &gt; 0:** sign(4) = +1 ⇒ <i>y</i><sub>2</sub> = 0.5 · 0 + 2.0 · √4 · 1 = 4.0.
3. **Отрицательная ветвь <i>u</i> = −9.0 &lt; 0:** sign(−9) = −1 ⇒ <i>y</i><sub>3</sub> = 0.5 · 4.0 + 2.0 · √9 · (−1) = 2.0 − 6.0 = −4.0.

### 5.4. Физические инварианты и сверка метода Эйлера с аналитикой (`Model3_1Test`)

1. **Инвариант покоя (`ZeroInputKeepsZeroStateAtRest`):** при нулевом начальном
   состоянии <i>y</i><sub>0</sub> = 0 и нулевом входном воздействии <i>u</i><sub>τ</sub> = 0 обе модели
   (1.7 и 2.9) на протяжении 10 тактов остаются в состоянии покоя (<i>y</i><sub>τ</sub> ≡ 0.0).
2. **Сходимость метода Эйлера к аналитическому решению (`EulerMethodApproximatesAnalyticalDecay`):**
   дифференциальное уравнение Блока 3 (**Модель 3.1**) имеет вид:

   <p align="center"><b><i>dy</i> / <i>dt</i> = −<i>a</i> · <i>y</i>, &emsp; <i>y</i>(0) = 1.0</b></p>

   Точное аналитическое решение задачи Коши: <i>y</i>(<i>t</i>) = <i>e</i><sup>−<i>a</i>·<i>t</i></sup>.
   При <i>a</i> = 0.5 в момент времени <i>t</i> = 1.0 с (1000 шагов метода Эйлера
   с малым шагом интегрирования Δ<i>t</i> = 0.001 с) численное решение
   сравнивается с эталоном <i>e</i><sup>−0.5</sup> ≈ 0.606531 с допуском `1e-3`.

### 5.5. Параметризованные тесты сходимости (`TEST_P`, п. 8)

При подаче постоянного ступенчатого сигнала <i>u</i><sub>τ</sub> = <i>u</i> = const устойчивая
линейная Модель 1.7 (|<i>a</i>| &lt; 1) при τ → ∞ выходит на установившееся
значение <i>y</i><sub>τ+1</sub> = <i>y</i><sub>τ</sub> = <i>y</i><sub>ss</sub>:

<p align="center"><b><i>y</i><sub>ss</sub> = <i>a</i> · <i>y</i><sub>ss</sub> + (<i>b</i><sub>1</sub> + <i>b</i><sub>2</sub> + <i>b</i><sub>3</sub>) · <i>u</i> &emsp;⇒&emsp; <i>y</i><sub>ss</sub> = <i>u</i> · (<i>b</i><sub>1</sub> + <i>b</i><sub>2</sub> + <i>b</i><sub>3</sub>) / (1 − <i>a</i>)</b></p>

Параметризованный тест `Model1_7ConvergenceTest` (`INSTANTIATE_TEST_SUITE_P`)
без дублирования кода проверяет выход на аналитическую асимптоту <i>y</i><sub>ss</sub> за
200 шагов на 3 различных наборах параметров:
* Набор 1: {<i>a</i> = 0.5, <i>b</i><sub>1</sub> = 1.0, <i>b</i><sub>2</sub> = 0.5, <i>b</i><sub>3</sub> = 0.2, <i>u</i> = 1.0} ⇒ <i>y</i><sub>ss</sub> = 1.7 / 0.5 = 3.4.
* Набор 2: {<i>a</i> = 0.2, <i>b</i><sub>1</sub> = 0.5, <i>b</i><sub>2</sub> = 0.3, <i>b</i><sub>3</sub> = 0.2, <i>u</i> = 2.0} ⇒ <i>y</i><sub>ss</sub> = 2.0 / 0.8 = 2.5.
* Набор 3: {<i>a</i> = −0.5, <i>b</i><sub>1</sub> = 1.0, <i>b</i><sub>2</sub> = 0.0, <i>b</i><sub>3</sub> = 0.0, <i>u</i> = 1.0} ⇒ <i>y</i><sub>ss</sub> = 1.0 / 1.5 ≈ 0.6667.

### 5.6. Мок-объекты (Google Mock) и подмена сигналов (п. 9)

В отличие от простой табличной подмены, в проекте применён полноценный фреймворк
**Google Mock**:
* создан мок-класс `MockSignalGenerator : public ISignalGenerator` с макросом
  `MOCK_METHOD(double, generate, (int tau), (const, override))`;
* в тесте `UsesMockGeneratorForControlRegimes` через `EXPECT_CALL` задаётся
  сценарий импульсного воздействия (<i>u</i><sub>0</sub> = 1.0, <i>u</i><sub>1</sub> = 0.0, <i>u</i><sub>2</sub> = 0.0) и
  контролируется как точность вычислений модели (2.0 → 2.0 → 1.0), так и
  кратность вызова генератора `Times(1)` на каждом такте;
* в тесте `StandardSignalGeneratorModes` проверяются все режимы штатного
  генератора: ступень (`type = 0`), единичный импульс (`type = 1`), гармоника
  sin(τ) (`type = 2`) и защита от некорректного кода режима (`type = 99` → 0.0).
